# 常见问题

## 模型生成完成，QQ 却没有收到回答

先查看 `model_completed` 之后是否有 `qq_send_failed`、`worker_failed` 或 `qq_send_failure_saved`。模型调用成功与 QQ 发送成功分别记录；发送错误的具体原因应结合 QQ 返回的错误说明判断。

新版本会在私有数据库中保存失败时实际发送的文本、可用的模型原文、HTTP 状态、错误码、错误响应和追踪 ID。管理员运行以下命令查看，日期中的 `+00:00` 表示 UTC，北京时间需加八小时：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/diagnostics.py --data-dir /var/lib/qqbotgpt --limit 5
```

`content` 是实际发给 QQ 的文本，`answer` 是格式转换前的模型原文；`stage=reasoning` 表示 DeepSeek 思考消息，其 `answer` 保存思考原文。等待提示或命令回复的 `answer` 为 `null`。`details` 保存可获得的错误信息，网络连接失败时可能没有 QQ 状态码或追踪 ID。记录保留最近七天、最多一百条，异常长内容会截断并标记。失败回答不进入聊天记忆，也不会自动重发。功能上线前未保存的回答无法通过此命令恢复。

## DeepSeek 没有显示思考过程

先用 `/模型` 确认当前会话使用 DeepSeek，再发送 `/思考 开启` 或 `/思考 高`。只有接口实际返回思考内容时才会显示；关闭思考或接口没有返回该字段时，只发送最终回答。当前等待模型响应完成后，依次发送思考过程和回答；一分钟仍未完成时沿用等待提示。

QQ 和微信都会展示 DeepSeek 实际返回的思考内容，两端最多发送三条思考消息，过长会标注省略。QQ 还受回复次数和有效期约束，接近时限时优先发最终回答；思考发送失败会记录诊断。微信会记录错误类型，并通过持久化队列保存发送进度。两端在思考发送失败时都会停止后续思考分段，继续尝试发送最终回答。

## 等待较久或出现模型超时

发送 `/超时` 查看当前会话等待上限，发送 `/超时 240` 可延长到 240 秒；也可通过 `/思考 高` 降低超高思考强度。处理满一分钟仍未完成时，机器人会先发送一次等待提示，完整回答稍后补发。提示不会延长总等待时间；到达上限会取消调用并提示超时。自动接话失败仍保持安静。

QQ 群聊被动回复有效期为五分钟，发送等待提示也沿用原消息 ID，程序会扣除排队时间并留出发送余量。此行为依据[腾讯官方发送消息文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)。网络连接、登录和附件下载也可能提前超时；日志中的 `model_failed` 包含实际耗时 `elapsed` 与本次预算 `budget`，便于定位。

## 机器人已启动，QQ 没有回复

按顺序检查：

1. 日志是否出现 `qq_gateway_ready`。没有出现时，检查 QQ 凭据、平台场景权限、WebSocket 设置及网络。
2. 当前私聊或群是否完成绑定。首次绑定用 `python bot.py --bind`；已有服务增加新群用 `python bot.py --new-binding`。
3. 群消息是否 @机器人。其他成员还需要配置 `group_members_can_chat: true` 并重启。
4. 同一个 QQ 机器人是否只运行一个实例。本机与服务器应保持一个运行位置。
5. `python bot.py --test-model` 能否返回回答。模型测试失败时，按提示检查对应服务的登录、Key 和额度。

搜索或较高思考强度可能延长等待时间。`/状态` 可以检查最近一次模型调用；服务器日志中的 `model_completed` 和 `reply_sent` 分别表示模型完成与 QQ 发送成功。

## 群里只有绑定账号能提问

将 `group_members_can_chat` 设为 `true` 并重启。开放后，已绑定群的其他成员可以 @提问；修改设置和清空记忆仍由绑定账号负责。新群需要单独绑定。

## 登录成功，模型仍提示未获授权

登录身份和使用计划额度都需要完成官方授权。先运行 `python chatgpt.py status` 查看状态，再运行 `python chatgpt.py models`。根据错误提示检查账户资格、所选工作区和服务可用地区，参见 [官方接入文档](https://developers.openai.com/siwc/quickstart)。

自定义 `data_dir` 时，确认 `chatgpt.py --data-dir ...` 与机器人配置指向同一目录。服务器登录流程见 [服务器部署](服务器部署.md)。

## ChatGPT 额度在哪里查看

在 [ChatGPT 设置 → Usage](https://chatgpt.com/#settings/Usage) 查看当前授权用量和限制。本程序的搜索使用同一份 ChatGPT 授权，模型返回的 token 统计可用于观察请求，账户额度以官方页面为准。DeepSeek 使用自己配置的 API Key 和对应服务额度。

## 服务器提示登录已失效，或登录已转交

已用 `export --move` 转交的登录由目标服务器继续使用和续期。在源电脑直接调用会提示已经转交。

需要重新授权服务器时，先停止服务器服务，在本机运行 `python chatgpt.py login --new`，再按部署文档导出、上传、导入和测试，成功后恢复服务。登录转移文件包含敏感凭据，验证成功后删除临时副本。

## 模型名或思考档位不可用

先在 QQ 中发送 `/模型 列表` 和 `/思考`，使用当前账户实际返回的选项。不同模型支持的思考档位有差异；不支持关闭思考的模型会拒绝 `/思考 关闭`，原设置保留。

修改配置文件影响默认选择。通过 QQ 命令设置过的会话会继续使用自己的选择，可发送 `/模型 默认` 恢复配置默认值。

## 网页搜索没有发生，或想查看来源

确认当前服务为 ChatGPT、`chatgpt_web_search` 为 `true`，并在改动配置后重启。明确提出“联网查一下……”可以表达搜索需要；普通聊天可能不使用工具。`/状态` 中的检索或网页读取次数显示最近一次真实调用结果。

默认聊天隐藏来源。可以在提问中说“附上来源”，或将 `chatgpt_show_sources` 设为 `true` 后重启，以始终显示来源。独立验证命令：

```bash
python chatgpt.py test --search "联网查一下 Python 官网目前推荐的稳定版，简短回答"
```

搜索能力仍取决于账户和模型支持。DeepSeek 当前未接入网页搜索。

## 回复为什么使用纯文本

QQ 文本消息会直接显示许多 Markdown 标记。程序统一处理标题、加粗、列表、引用、链接和表格，保留可读文字；代码去除外围围栏，保留内容和缩进。单条回复最长 3000 个字符，超长内容会缩短。

## 如何清除记忆和调整容量

绑定账号发送 `/清空` 删除当前会话的聊天记录，模型和其他设置继续保留。`/记忆 200` 调整消息容量；`/记忆 过期 0` 关闭闲置过期。容量范围 10～500 条，单次送入模型的聊天正文还会限制在 60000 个字符以内。

容量增加会增加可带入的上下文，已经淘汰或过期的内容无法恢复。私聊与群聊分别保存；同一群成员共用本群上下文。

## 如何反馈问题

先运行自动化测试和模型连接测试，再提供系统、Python 版本、所选服务、复现步骤与脱敏错误日志。不要上传真实配置、`.data`、登录导出文件、绑定口令或聊天数据库。具体说明见 [贡献指南](../CONTRIBUTING.md)。
