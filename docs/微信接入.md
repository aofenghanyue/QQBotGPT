# 微信 ClawBot 私聊

微信入口复用现有 ChatGPT / DeepSeek、模型切换和 SQLite 记忆，支持多个微信号同时使用。每个微信号分别扫码，保存独立登录、聊天记忆和设置；只接受该次扫码的微信号发送的私聊。群消息、其他发送者和机器人自身消息会在保存和调用模型之前被过滤。

DeepSeek 开启思考后，微信与 QQ 一样，在模型完成时先发送接口返回的思考过程，再单独发送最终回答。两端共用分段格式，思考最多三条、每条不超过 3000 字符，超长部分会标注省略。关闭思考或接口未返回思考内容时只发送回答。思考过程不进入聊天记忆和后续模型请求。

微信将待发思考分段和发送进度保存在当前账号的消息队列中。发送完成后清理；进程重启后跳过已确认成功的分段，未完成的消息使用原有消息标识继续发送，无需重新调用模型。思考分段发送失败或超过五秒时，会停止后续分段并尝试发送最终回答，同时提示部分思考未能发送；最终回答发送失败时沿用队列重试。微信授权失效时暂停发送，需要重新扫码，新登录仍按原有规则清理旧登录的待发消息。

支持文字对话；ChatGPT 模型还可理解图片和阅读文件。每轮只带最近两张图片或紧邻问题的一个文件，回复引用附件、准确文件名或明确指向最近附件时可重读。普通追问不重复上传历史附件。单独发送附件后请在 5 分钟内紧接着提问，单个附件最多 20 MiB；格式和引用索引保留规则见 [图片和文件阅读](../README.md#图片和文件阅读)。语音、视频暂未接入。模型服务沿用部署者配置的凭据和额度。

## 准备

1. 更新微信，在「我 → 设置 → 插件」检查是否能启用微信 ClawBot。入口以账号和客户端实际开放情况为准。
2. 安装项目依赖：`python -m pip install -r requirements.txt`。
3. 准备模型配置。可以沿用 QQ 的配置文件，微信入口无需 `app_id` 和 `app_secret`。也可以复制 `config.example.json` 为自己的 `config.json`，填写模型相关设置。

配置文件中的 `data_dir`、`deepseek_key_file` 相对于配置文件所在目录解析。微信数据放在 `<data_dir>/weixin/`；QQ 的数据库保持在 `<data_dir>/state.db`。微信登录凭据和记忆与 QQ 分开保存，ChatGPT 登录凭据可由同一部署设备上的进程共享。

ChatGPT 已转交服务器的情况下，在服务器运行微信服务并沿用服务器配置。本机如需独立使用，应建立本机自己的模型连接。模型配置与登录步骤见 [README](../README.md) 和 [服务器部署](服务器部署.md)。

## 连接两个微信号

在项目目录执行，先用第一个微信号扫码：

```bash
python weixin.py --config config.json login --account main
```

终端显示二维码，同时在受保护的数据目录内生成临时 `login.png`。用手机微信扫码确认；若微信显示连接验证码，在终端输入对应数字。登录成功或流程结束后会删除临时二维码图片。

再用第二个微信号扫码：

```bash
python weixin.py --config config.json login --account second
```

`main` 和 `second` 是自己选的本地别名，后续重新登录时沿用相同别名。别名使用小写字母开头的字母、数字、下划线或短横线，最多32位。两个别名需连接不同微信号；同一个微信号重复绑定到另一个别名时会提示使用原别名。

启动全部账号：

```bash
python weixin.py --config config.json run
```

分别在两个微信号的 ClawBot 窗口发送 `/帮助` 和一句普通问题。各号独立记忆，`/模型`、`/思考`、`/记忆`、`/清空` 仅影响当前号。

服务运行时，可以在另一个终端执行 `login --account third` 增加第三个微信号。服务会自动加载新增或更新的登录。使用 `run --account main` 可只运行指定账号；同一数据目录同时只允许运行一个微信服务进程。

其他命令：

```bash
python weixin.py --config config.json accounts
python weixin.py --config config.json test-model
```

`accounts` 只显示别名和最近记录的状态，不验证实时在线状态。`test-model` 只测试模型，不连接微信。

## 常驻服务器

借用朋友的服务器部署时，请使用独立的运行用户、程序目录、配置、数据目录和服务名，并同步修改服务模板中的对应字段。默认使用自己的模型凭据和额度，保留服务器上已有实例的配置与运行状态。

已经按 QQ 部署文档设置 `/etc/qqbotgpt/config.json` 和 `/var/lib/qqbotgpt` 时，为微信单独建立 `/opt/qqbotgpt-weixin`，将本次版本的 `bot.py`、`chatgpt.py`、`attachments.py`、`diagnostics.py`、`weixin.py`、`requirements.txt` 放入该目录。建立独立运行环境，然后在服务器终端依次扫码：

```bash
sudo python3 -m venv /opt/qqbotgpt-weixin/.venv
sudo /opt/qqbotgpt-weixin/.venv/bin/python -m pip install -r /opt/qqbotgpt-weixin/requirements.txt
sudo -u qqbotgpt /opt/qqbotgpt-weixin/.venv/bin/python /opt/qqbotgpt-weixin/weixin.py --config /etc/qqbotgpt/config.json login --account main
sudo -u qqbotgpt /opt/qqbotgpt-weixin/.venv/bin/python /opt/qqbotgpt-weixin/weixin.py --config /etc/qqbotgpt/config.json login --account second
sudo -u qqbotgpt /opt/qqbotgpt-weixin/.venv/bin/python /opt/qqbotgpt-weixin/weixin.py --config /etc/qqbotgpt/config.json test-model
```

安装项目提供的 `deploy/weixinbotgpt.service` 后启动：

```bash
sudo install -m 644 deploy/weixinbotgpt.service /etc/systemd/system/weixinbotgpt.service
sudo systemctl daemon-reload
sudo systemctl enable --now weixinbotgpt
sudo systemctl status weixinbotgpt --no-pager
sudo journalctl -u weixinbotgpt -n 40 --no-pager
```

微信通过出站 HTTPS 长轮询接收消息，无需开放入站端口。QQ 和微信使用独立的服务与数据库。模型登录续期期间若另一进程短暂占用凭据锁，本次请求会提示稍后重试。

## 恢复与数据

- 网络异常时自动退避重连；服务重启后恢复本地轮询游标、待处理消息和记忆。
- 收到消息时，待处理消息和新游标在同一个 SQLite 事务中保存。发送失败会保存生成的回答，重试沿用同一个 `client_id`，避免再次调用模型。网络中断发生在服务端已收取回复、客户端尚未收到确认的瞬间时，最终是否去重取决于微信服务端行为，无法承诺绝对只发送一次。
- 超过一小时的入站消息会跳过，避免执行陈旧指令。已完成消息只保留一天的去重标识，删除其中的原始消息和回复缓存；聊天记忆按 `/记忆` 设置保存。
- 收到授权过期或受限响应时，只停止对应账号的请求，其他账号继续运行。用同一别名重新 `login`，服务会自动加载新凭据；旧登录尚未完成的回复会丢弃，避免使用过期回复上下文。
- 重新扫码到同一个微信机器人身份和用户身份时，记忆可继续使用；身份发生变化时切换到独立会话。`/清空` 清除当前会话记忆。
- 数据目录使用当前部署用户可访问的权限。二维码、凭据、消息正文和回复上下文均不应公开；常规日志只记录本地账号别名、状态和错误类型。

## 协议依据与验证范围

消息收发与登录字段核对自腾讯官方 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，版本 `2.4.10`，源码提交 `874637a0dbc24050f72d1385add4fc6170a2d726`。本项目独立实现 Python 适配层，无需安装 OpenClaw；微信通道的可用性以实际服务端响应为准。

图片和文件下载、解密及引用字段于 2026-10-19 核对官方仓库的 `src/media/media-download.ts`、`src/cdn/pic-decrypt.ts`、`src/cdn/cdn-url.ts` 和 `src/api/types.ts`。优先使用 `full_url`，兼容 `encrypt_query_param`；支持图片十六进制密钥、Base64 原始密钥及 Base64 十六进制字符串密钥。附件处理使用模拟下载和真实 AES 解密测试，真实微信图片、文件与引用消息仍需部署账号验收。

协议参考文件：`src/auth/login-qr.ts`、`src/api/api.ts`、`src/api/types.ts`、`src/messaging/send.ts`。已覆盖扫码确认、验证码、官方域名跳转、过期授权、多账号隔离、群聊拒收、重复消息、重启续发和文字协议的模拟测试。服务端会以 `application/octet-stream` 返回 JSON，客户端按 JSON 内容解析，并有本地 HTTP 回归测试覆盖该行为。

已在 Windows Python 3.12 和 Linux Python 3.10 验证自动化测试；在 Azure Linux 上完成第一个微信号的真实扫码、`/帮助` 回复及 ChatGPT 文字对话，用户确认收发成功。多个账号的隔离与自动加载已通过模拟测试，第二个微信号尚待实际扫码验证。
