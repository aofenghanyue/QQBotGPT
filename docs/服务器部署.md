# 服务器部署

这份说明用于把 QQBotGPT 部署到自己的 Ubuntu 或 Debian 服务器。需要能够通过 SSH 登录服务器，并执行 `sudo`。最终由系统服务保持机器人运行，关闭本机终端后也能继续使用。

先按 [README](../README.md) 在本机准备代码、Python 环境和模型凭据。使用 ChatGPT 时，先完成本机登录和连接测试。以下命令分为“本机”和“服务器”，请在标明的位置执行。

配置项和相对路径规则见 [配置参考](配置参考.md)，连接和登录问题见 [常见问题](常见问题.md)。服务器示例始终使用绝对路径；后续生成新群口令时，也应使用同一份配置。

## 1. 上传程序

在本机项目目录打开 PowerShell，将下面的 `user@server` 换成自己的 SSH 用户名和服务器地址。`$Target` 在后续本机上传命令中沿用；重开终端后需要重新赋值。

```powershell
$Target = 'user@server'
ssh $Target 'mkdir -p ~/qqbotgpt-src && chmod 700 ~/qqbotgpt-src'
scp bot.py chatgpt.py requirements.txt config.example.json deploy/qqbotgpt.service "${Target}:~/qqbotgpt-src/"
ssh $Target
```

最后一条命令进入服务器终端。后续程序文件放在 `/opt/qqbotgpt`，私人配置放在 `/etc/qqbotgpt`，登录和记忆放在 `/var/lib/qqbotgpt`。

## 2. 安装和配置

在服务器执行：

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv
id qqbotgpt >/dev/null 2>&1 || sudo useradd --system --home /var/lib/qqbotgpt --shell /usr/sbin/nologin qqbotgpt
sudo install -d -o root -g root -m 755 /opt/qqbotgpt
sudo install -d -o root -g qqbotgpt -m 750 /etc/qqbotgpt
sudo install -d -o qqbotgpt -g qqbotgpt -m 700 /var/lib/qqbotgpt
sudo install -m 644 ~/qqbotgpt-src/bot.py ~/qqbotgpt-src/chatgpt.py ~/qqbotgpt-src/requirements.txt /opt/qqbotgpt/
sudo python3 -m venv /opt/qqbotgpt/.venv
sudo /opt/qqbotgpt/.venv/bin/python -m pip install -r /opt/qqbotgpt/requirements.txt
sudo install -o root -g qqbotgpt -m 640 ~/qqbotgpt-src/config.example.json /etc/qqbotgpt/config.json
sudoedit /etc/qqbotgpt/config.json
```

在编辑器中填写 QQ 的 `app_id` 和 `app_secret`，选择 `provider`，并将以下两项改为服务器上的路径：

```json
"data_dir": "/var/lib/qqbotgpt",
"deepseek_key_file": "/etc/qqbotgpt/deepseek.key"
```

这是现有 JSON 中的两个字段，替换对应值即可；保留文件的其余字段和正确的逗号。接下来准备所选模型服务。

## 3. 准备模型服务

### 使用 ChatGPT

服务器需要自己的设备标识。先在服务器执行：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/chatgpt.py --data-dir /var/lib/qqbotgpt init-host
```

在服务器终端执行 `exit`，返回刚才的本机 PowerShell 项目目录。停止正在运行的本机机器人，再导出已登录的账户并上传：

```powershell
python chatgpt.py export --move
scp .data/chatgpt-transfer.json "${Target}:~/qqbotgpt-src/"
```

`--move` 会停止本机使用这份登录，后续由服务器负责续期。导出文件包含登录凭据，只传到自己的服务器。这一步按照 [OpenAI 自托管文档](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)转移会话；账户资格和服务可用地区仍需符合官方要求。

上传完成后，在本机执行 `ssh $Target` 再次进入服务器，然后导入并测试：

```bash
sudo install -o qqbotgpt -g qqbotgpt -m 600 ~/qqbotgpt-src/chatgpt-transfer.json /var/lib/qqbotgpt/chatgpt-transfer.json
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/chatgpt.py --data-dir /var/lib/qqbotgpt import /var/lib/qqbotgpt/chatgpt-transfer.json
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/bot.py --config /etc/qqbotgpt/config.json --provider chatgpt --test-model
```

看到“连接成功”后，删除本机 `.data/chatgpt-transfer.json`，以及服务器 `~/qqbotgpt-src/chatgpt-transfer.json` 和 `/var/lib/qqbotgpt/chatgpt-transfer.json` 这两份临时文件。正式登录已保存到服务器的 `/var/lib/qqbotgpt/chatgpt.json`，需要保留。

### 使用 DeepSeek

在服务器创建 API Key 文件：

```bash
sudo touch /etc/qqbotgpt/deepseek.key
sudo chown root:qqbotgpt /etc/qqbotgpt/deepseek.key
sudo chmod 640 /etc/qqbotgpt/deepseek.key
sudoedit /etc/qqbotgpt/deepseek.key
```

写入自己的 API Key 后保存，再测试：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/bot.py --config /etc/qqbotgpt/config.json --provider deepseek --test-model
```

看到“连接成功”即可继续。需要两种服务随时切换时，分别完成这两部分；`--test-model` 只调用模型，不连接 QQ。

## 4. 绑定 QQ 并保持运行

先停止本机或其他服务器上使用同一个 QQ 机器人的程序，再在服务器前台启动：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/bot.py --config /etc/qqbotgpt/config.json --bind
```

终端显示 `/绑定 …` 口令和 `qq_gateway_ready` 后，用自己的 QQ 私聊机器人并发送口令。收到绑定确认，再发送“请只回复：连接成功”。收到回答，说明登录、QQ 收发和模型调用已连通。

绑定信息会保存。按 `Ctrl+C` 停止前台程序，再安装常驻服务：

```bash
sudo install -m 644 ~/qqbotgpt-src/qqbotgpt.service /etc/systemd/system/qqbotgpt.service
sudo systemctl daemon-reload
sudo systemctl enable --now qqbotgpt
sudo systemctl is-active qqbotgpt
sudo journalctl -u qqbotgpt -n 20 --no-pager
```

`is-active` 应输出 `active`，日志应出现 `qq_gateway_ready`。再发一条 QQ 消息确认收到回答，就可以关闭 SSH 终端。服务会在开机时启动，异常退出后自动重启。

需要新增一个群时，在服务器生成口令，服务可以继续运行：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/bot.py --config /etc/qqbotgpt/config.json --new-binding
```

在新群里 @机器人发送口令，收到确认即完成绑定。口令 10 分钟内有效，仅能使用一次，已有绑定会保留。需要允许所有群成员 @提问时，将配置中的 `group_members_can_chat` 改为 `true`，再执行 `sudo systemctl restart qqbotgpt`；修改设置仍限绑定账号。

## 日常维护

**切换服务或模型：** 绑定账号可以直接在 QQ 中发送 `/模型 chatgpt <模型名>` 或 `/模型 deepseek deepseek-flash`，用 `/思考 高` 设置强度。模型名从 `/模型 列表` 的实际结果中选择。设置只影响当前会话，立即用于下一次请求。`/思考` 会显示当前可选档位，`/状态` 查看当前设置。

**网页搜索：** ChatGPT 默认按需搜索，直接在 QQ 中说“联网查一下……”即可。回复默认只显示聊天正文，索要出处时再附网址；`/状态` 显示最近一次实际检索、读取网页的次数。配置项 `chatgpt_web_search` 控制搜索，`chatgpt_show_sources` 控制是否始终附来源，修改后重启服务。

可以先在服务器终端单独测试，成功时会显示回答、搜索次数和来源网址：

```bash
sudo -u qqbotgpt /opt/qqbotgpt/.venv/bin/python /opt/qqbotgpt/chatgpt.py --data-dir /var/lib/qqbotgpt test --search "联网查一下 Python 官网最新稳定版，简短回答"
```

终端测试不连接 QQ。搜索仍使用已授权的 ChatGPT 计划，是否可用由模型和账户权限决定；出现权限或能力限制错误时，按提示处理。DeepSeek 当前未接入网页搜索。

需要修改所有未单独设置会话的默认值时，用 `sudoedit /etc/qqbotgpt/config.json` 修改 `provider`、`chatgpt_model` 或 `deepseek_model`，再执行 `sudo systemctl restart qqbotgpt`。有独立设置的会话可以发送 `/模型 默认` 恢复配置文件中的选择。

**查看问题：** 执行 `sudo journalctl -u qqbotgpt -n 50 --no-pager`。没有 `qq_gateway_ready` 时先检查 QQ 凭据、WebSocket 设置和服务器网络；模型报错时运行第 3 步的连接测试。已连接却不回应时，确认当前私聊或群已绑定，并在群聊中 @机器人。其他群成员需要启用 `group_members_can_chat` 才能使用。

**重新登录 ChatGPT：** 停止服务器服务。在本机运行 `python chatgpt.py login --new`，重新完成第 3 步的导出、上传、导入和测试，再启动服务。本机之前的登录已经转交服务器，因此这里使用 `--new`。

**更新代码：** 先停止服务，备份 `/opt/qqbotgpt`、`/etc/qqbotgpt` 和 `/var/lib/qqbotgpt` 到仅管理员可读的目录。上传新代码，替换程序文件并安装依赖，保留现有配置和数据。连接测试通过后启动服务，再通过 QQ 发消息验证；失败时可停止服务并恢复备份。不要重新用示例配置覆盖自己的配置。

机器人通过 WebSocket 主动连接 QQ，正常运行无需开放新的入站端口。
